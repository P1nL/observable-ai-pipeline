# Observable AI Pipeline

一个支持步骤级重试、进程中断恢复、检查点、结果复用与 GPU 资源观测的 AI 长任务执行管线 MVP。

以动画素材处理为演示场景，AI 计算允许 MOCK，执行状态、持久化、故障恢复和产物提交不能只做 UI 模拟。

## 当前状态

**阶段：P0，规划与仓库基线。尚未实现或验证执行引擎。**

- 已建立 PRD、路线图、执行规范、实施计划和故障验收场景。
- 已提供可机读的示例 DAG 和待接入的环境配置模板。
- 尚未提供可运行 API、Worker、数据库迁移、前端或 Docker Compose。
- MOCK GPU 计划不代表真实 CUDA、显存隔离或硬件故障已验证。
- 本仓库尚未选择许可证。

## 核心目标

1. HTTP 提交后立即获得任务 ID，任务不依赖请求或页面连接存活。
2. 分开记录 Task、Step、Attempt；重试保留失败历史。
3. Worker 中断后从已持久化状态接管，而不是所有步骤从头开始。
4. 复用已完成步骤，为帧生成步骤实现批次检查点。
5. 显示任务状态、执行历史、等待原因及 GPU 槽位占用。
6. 支持小时级运行，不把短租约当作模型运行上限。

## 长任务策略

**模型完成优先：租约周期性续期；默认不设置步骤硬执行时限和任务总截止时间。**

初始配置约定为 30 秒心跳、300 秒租约。两者用于存活检测和执行所有权，正常续期的步骤可以运行数小时。耗时超出软阈值只产生告警，不杀进程。用户取消、确认的执行失败、无法续租导致所有权失效仍需处理。故障演示使用独立快测配置。

这不是“无条件保证完成”：不可恢复输入、资源永远不可用、存储损毁、执行永久卡住或外部服务持续失败，仍需明确报错、告警或人工介入。详见 [长任务决策](docs/ADR-001-long-running-execution.md)。

## 下一步不是继续扩写文档

先完成 P1 垂直闭环：**提交任务 → 数据库保存 → 独立 Worker 执行一个 MOCK 步骤 → 保存产物 → 查询状态和历史**。随后在 P2 验证运行时间超过一个租约周期仍正常、杀死 Worker 可接管、旧 Attempt 不能覆盖新结果。

所有“通过”结论须来自实际运行。本阶段未启动业务服务、连接真实模型或 GPU，也没有对外开放 API。
