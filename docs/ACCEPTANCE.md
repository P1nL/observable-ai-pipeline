以真实 API/数据库、Worker 进程、持久化产物为主。前端是状态展示，不替代执行证据。运行配置与关键观察记录在开发记录中，不为“证明做完”额外生成校验清单或哈希文件。

## 2. 边界

- fast-recovery 只缩短演示时钟，不替代小时级真实运行观测；不能声称已经完成数小时压力测试。
- MockGPUProvider 验收的是槽位和状态逻辑，不是 CUDA、硬件故障或实际显存隔离。
- 本地持久化卷能覆盖进程/容器重启，不覆盖磁盘损毁或未保留卷的数据删除。
- 不保证外部收费 API 的 exactly-once 提交；真实接入需要提供方幂等/查询能力。

## 3. 记录格式

每个实际执行的场景记录：日期、配置、注入方式、Task/Attempt 标识、观察结果、未覆盖边界、是否通过。只把运行后实际观察到的结果写成“通过”。
