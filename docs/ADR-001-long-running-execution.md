# ADR-001：完成优先的长任务执行策略

日期：2026-10-24。状态：长任务策略维持不变；已有 Supervisor/续租原型及快速时钟回归，不等于小时级或 GPU 恢复验收。三天工期不改变默认时间策略。

## 背景

用户要求单次模型执行和整体任务能够完成，不因偏短的租约或超时配置被误杀。早期演示值偏向快速发现故障，不适合作为小时级任务的默认运行策略。

## 决策

1. 将租约与模型运行时长彻底分开。正常运行的 Attempt 通过持续续租可以跨越任意多个租约周期。
2. 默认心跳 30 秒、租约 300 秒、扫描 5 秒，容忍短暂调度/网络抖动；这些是初始设计值，不是实测最优参数。
3. 默认 attempt_hard_timeout 和 task_deadline 均为 null。环境模板的 0 只作为“关闭”表示，载入后转为 null。
4. 步骤超过 6 小时、任务超过 24 小时先产生软告警，不强制停止。阈值后续依真实耗时调整。
5. 如用户明确指定硬时限，将其冻结在任务配置并展示；超限按明确原因处理，不混入“模型失败”。
6. 使用独立 Supervisor 监管计算子进程并续租；模型阻塞不应阻塞心跳。Supervisor 同时检查子进程退出，避免给已死计算持续续租。
7. 无法续租直至过期仍代表失去执行所有权。旧 Worker 不得越权提交；GPU 进程是否停止需要独立确认。
8. 自动重试有限次；重试耗尽后提供人工恢复，保留已成功步骤和检查点。

## 三种时间不是一回事

| 时间 | 回答的问题 | 默认行为 |
| --- | --- | --- |
| 租约 | 谁当前有权执行并提交？ | 每次续租向后延长，不是累计上限 |
| Attempt 硬时限 | 是否允许一次计算运行超过某时长？ | 默认不限制，可显式设置 |
| Task 截止时间 | 是否允许排队、重试和整个流程超过某时长？ | 默认不限制，可显式设置 |

HTTP 请求超时和前端断线不属于上述业务截止时间。模型提供方自身的限额/超时也不能靠修改本地租约解除；真实接入时需检查外部协议，必要时采用异步任务 ID 和查询恢复。

## 代价与完成边界

- 租约加长会使真正崩溃的自动发现更慢；初始最大发现等待约为一个租约周期加扫描周期，而不是承诺固定秒级恢复。
- 无硬时限意味着卡住的模型可能长期占卡，需观测、告警、故障停止和后续按工作负载配置时限；不因此承诺完整取消 API/UI。
- 心跳证明监督进程存活，不证明业务必定推进；进度停滞不能自动等同于失败。
- 外部依赖持续不可用、数据损毁、不可恢复输入和永久计算故障无法通过无限等待保证成功。
- 本项目保证的是：健康长任务不因默认短时限被中断，成功工作可复用，可恢复故障有明确接管路径，不是数学意义上对所有输入都最终成功。

## 拒绝的方案

- 只将所有超时设置成极大值：会延迟真正故障识别，而且不能解决模型计算阻塞心跳。
- 用模型回调发送唯一心跳：长时间无回调会被误判失联。
- 完全取消租约与 fencing：旧/新 Worker 可能同时提交权威结果。
- 用无界重试表达“保证完成”：永久错误会持续消耗资源且无法给出清晰结果。

## 验收

- 在独立快测配置下让模型步骤运行至少三个租约周期，仍只有一个成功 Attempt。
- 模型不报告进度但 Supervisor 正常时不因租约过期被杀。
- 子进程实际退出时，不继续为死任务续租。
- 杀死 Supervisor 后可以失效接管，旧 Attempt 提交被拒绝。
- 配置了显式硬时限时能按该策略停止/隔离；默认配置不触发这种停止。

CPU MOCK 快速回归、Worker 内置扫描接管、运行中旧代次提交隔离、本地单模拟槽位隔离/清理及 A12 真实 PostgreSQL 停机/重启专项已执行，状态见 [验收表](ACCEPTANCE.md) 与开发记录。A12 使用显式 15 秒和 4 秒测试租约，不改变正常 30 秒心跳 / 300 秒租约；真实 GPU 和小时级运行仍未验收，不能用快速时钟或模拟结果替代。

## 步骤级外部后端的沿用（2026-10-25）

本次外部托管不改变以上决策。中心监督循环与 HTTP I/O 线程分离，独立执行器服务的 watchdog 又与固定计算子进程分离。只有中心成功续租后才发送新的绝对租约到期时间；服务 `/health` 可用、命令响应成功、进程 RUNNING 与业务进度分别处理，不能互相代替。

外部 RPC 默认 0.5 秒超时不是步骤上限；正常默认仍 30 秒心跳、300 秒可续期租约，硬执行时限和任务总截止时间关闭。服务确认物理退出且候选结果经中央 fencing 后才成功；失联、身份不确定或输出 reader 丢失不允许伪造成功/释放资源。服务重启按原身份停止旧进程，由中心决定新 Attempt 和检查点复用，不宣称任意作业接管或 exactly-once 计算。外部快速时钟验证单独记录，不替代小时级、跨机时钟/网络分区或真实 GPU 验收。

## 预配置节点沿用（2026-10-25）

多个节点不改变 30/300 或关闭硬时限的默认策略。恢复扫描及各节点能力/存储观察在 Worker 独立后台线程执行，单个节点 RPC 阻塞不能挤占唯一续租路径。接单状态、网络存活、实际进度、租约所有权和物理退出分别记录。旧资源归属原节点/设备/Attempt/代次；状态库 incarnation 的 state_id 必须与原命令相同，换空状态库的退出墓碑不作为清理依据。真实跨设备部署还需满足时钟、网络、TLS、共享挂载条件，本地快测不替代这项验收。
