## 2. P1：最小垂直闭环

### 建议目录（本阶段尚未创建实现）

- backend/app/api/：提交与查询接口。
- backend/app/domain/：状态枚举、StepSpec、错误分类和 DTO。
- backend/app/persistence/：数据表、仓储和数据库事务。
- backend/app/worker/：Supervisor、子进程协议和 MOCK 处理器。
- backend/app/coordinator/：任务推进与后续恢复逻辑。
- backend/migrations/：显式数据库迁移。
- backend/tests/：针对已实现行为的单元/集成测试。
- frontend/：P4 再创建，避免先做伪进度页面。
- compose.yaml：P1 最小服务，后续逐步补齐。

### 实施顺序

1. 确定并锁定实际 Python/依赖版本；用项目隔离环境，不更改全局环境。
2. 建立状态枚举、请求/响应、StepSpec 与配置模型，明确 null/0 的时限语义。
3. 添加 PostgreSQL 迁移，先实现 tasks/steps/attempts/events/artifacts 的必要字段。
4. 建立一个 synthetic 输入、单 MOCK 步骤的 smoke-v1 流程。该流程只用于验证通路，不冒充完整示例 DAG。
5. POST 提交在事务中保存任务后返回；Worker 独立运行并领取、执行和提交结果。
6. GET 接口展示真实状态、Attempt、事件和可读取产物。
7. 用最小 Compose 验证启动及 API 重启后任务仍可查询。
8. 加入能运行的最小 CI：已实现模块的测试与配置校验。不先堆复杂覆盖率门禁。

P1 完成标准：不连接真实模型、不依赖前端，一个任务能从提交走到产物。此时不能宣称失联恢复、GPU 调度或整个 MVP 已完成。

## 3. P2：先验证关键恢复语义

按顺序补充：

1. 固定 DAG 的依赖推进与失败传播。
2. 独立 Supervisor 心跳、租约续期、失联检测和 fencing。
3. 运行超过至少三个租约周期，不产生重复 Attempt。
4. 错误分类、有限自动重试、人工恢复和历史保留。
5. 批次产物 + 检查点协议、提交中断窗口。
6. 缓存键、成功步骤复用与缓存来源。

只对变更行为做必要验证；跨租约存活、接管、旧提交拒绝、检查点恢复是核心必测，不用额外审查任务或证明文件替代运行。

## 4. P3 / P4

- P3 将 GPU 槽位分配纳入领取事务，处理失联隔离和节点恢复对账。
- P4 用数据库/API 的真实状态制作任务列表、任务详情和资源面板。
- 所有故障注入仅在显式演示/测试模式开启，不通过公网匿名开放。
- 只使用合成示例素材；如后续添加真实素材，应明确来源与可发布范围。
- 收尾整理实际启动命令、验收结果、已知限制、token/时间与失败案例，不夸大 MOCK 为真实 GPU 证据。

## 5. 当前无需阻塞的问题

- 没有真实 GPU：使用 MOCK 槽位即可完成执行逻辑验收。
- 没有模型密钥：本 MVP 不需要。
- 没有公网服务：公开仓库是可选交付条件之一，先完成可复现仓库。
- 未选择许可证：保持未选择状态，不自动代用户授予许可。

接入真实 GPU、公开写 API、外部收费模型或改变 MVP 范围时，再明确环境和授权，不提前增加无关基础设施。
