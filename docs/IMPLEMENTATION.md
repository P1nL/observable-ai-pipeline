## 2. P1：已落地的最小垂直闭环

### 实际目录（不创建空壳模块）

- backend/app/api.py：提交、查询、产物下载、人工恢复与只读模拟槽位查询。
- backend/app/domain.py、config.py：状态、固定流程、错误分类、请求与冻结配置。
- backend/app/db.py、repository.py：显式迁移、短事务、持久化、领取和已写出的 fencing。
- backend/app/worker.py、executor.py、artifacts.py：独立 Supervisor、空闲/计算中扫描、计算子进程和不可变文件。
- backend/app/processes.py：本地执行器身份校验、PID 复用隔离和有界停止确认。
- backend/app/backends.py：最小 ExecutionHandle、本地子进程与外部 HTTP 适配；具体计算仍复用 executor.py/media.py。
- backend/app/external_protocol.py、external_service.py：绑定认证协议、独立 SQLite 启动意图/事件、固定计算子进程和 watchdog；没有新调度服务或插件目录。
- backend/app/coordinator.py：保留的兼容入口；启动及验收不再需要该进程，不建设独立调度服务。
- backend/migrations/：001 执行表，002 增量建立单模拟槽位与执行器身份；不重写既有迁移。
- backend/app/inputs.py、media.py：有限静态图片上传、实际像素变换、PNG 帧和 GIF、嵌套媒体引用验证；003 上传元数据、004 成功步骤缓存均为增量迁移。
- 005_external_execution.sql：Attempt 后端身份与同事务持久化命令/退出事实；历史 Attempt 默认 local，不改写冻结任务。
- backend/tests/：针对已实现行为的单元/集成测试。
- backend/app/web/：同源静态 HTML/CSS/原生 JS 任务详情页，由 API 直接提供；没有独立 frontend/、构建工具或插件体系。
- compose.yaml：独立 PostgreSQL，API/Worker 用根目录 .venv 分进程运行。

### 实施顺序

1. 确定并锁定实际 Python/依赖版本；用项目隔离环境，不更改全局环境。
2. 建立状态枚举、请求/响应、StepSpec 与配置模型，明确 null/0 的时限语义。
3. PostgreSQL 迁移包含 tasks/steps/step_attempts/events/artifacts/recovery_operations，不预建 GPU/节点资源表。
4. 内部 smoke-v1 单步后接固定 animation-v1：normalize_asset → generate_frames → encode_package，不开放任意/并行 DAG。
5. POST 提交在事务中保存任务后返回；Worker 独立运行并领取、执行和提交结果。
6. GET 接口展示真实状态、Attempt、事件和可读取产物。
7. 用最小 Compose 验证启动及 API 重启后任务仍可查询。
8. 加入能运行的最小 CI：已实现模块的测试与配置校验。不先堆复杂覆盖率门禁。

P1 完成标准：正常三步、持久化、产物可读、API 重启不中断独立 Worker，并记录一次 Worker 中断观察。原请求下提前写出的恢复代码保留，跨任务缓存入口关闭并拒绝开启；不把中断观察或局部回归当作第二阶段完成。第一步达到这些条件后即收尾，不自行扩展全部 MVP。启动与测试命令见 README。

## 3. P2：先验证关键恢复语义

本阶段现已获授权实施恢复扫描、检查点接管、运行中新旧代次提交隔离和单模拟 GPU 槽位验收。已有相关代码保留；不扩展前端、通用编排或真实 GPU。按顺序完成：

1. 收敛固定线性流程的恢复扫描运行方式及失败传播，不建设通用 DAG。
2. 独立 Supervisor 心跳、租约续期、失联检测和 fencing。
3. 运行超过至少三个租约周期，不产生重复 Attempt。
4. 错误分类、有限自动重试、人工恢复和历史保留。
5. 批次产物 + 检查点协议、提交中断窗口。
6. 原 P2 仅同任务恢复成功步骤/产物；本轮新增授权的跨任务缓存见后文增强范围，不改写该历史阶段。

当前这组授权项已实现并直接验证，测试不再启动独立 coordinator。Worker 空闲和监督中均扫描；单模拟槽位在登记执行器身份后才允许计算，失联先隔离，确认退出并匹配原 owner/generation 后再释放。该轮结束时未自行进入页面；后续根据用户新增授权，先完成 A12 再进入 P4。具体证据与未覆盖专项见验收表/开发记录。

只对变更行为做必要验证；跨租约存活、接管、旧提交拒绝、检查点恢复是核心必测，不用额外审查任务或证明文件替代运行。

## 5. 当前无需阻塞的问题

### 两批增强的实际落点

- 第一批不接真实模型：静态 PNG/JPEG 8 MiB/16MP/8192 边长，实际读图、最长边 256、最多 120 帧；API/页面提供 GIF 和 JSON。基本 cancel 先撤销派发/提交权，退出确认后终结，身份未知保持取消中/隔离。
- 第二批图在服务端固定版本化，不接受自定义代码。两个 Worker 可领取两个 READY 分支，CPU 默认容量 2、GPU 模拟槽位 1，汇合等待全部依赖；失败恢复保留成功分支。历史三步按原快照执行。
- 兼容缓存只在来源 Task 成功时发布；核实实际文件、引用链及作用域/版本/参数/seed，CACHED 保留来源和引用，不伪造 Attempt。publish_result 必须本任务提交；支持 bypass_cache 与 generation_tag。
- API/全部 Worker 配置一致并在升级迁移后重启；原开发库有一条缺进程创建时间的 P1 CPU LOST，未伪造清理，本轮预览显式容量 3，保留 1 个未知占用后余下两路并行。新库默认 2，不为演示解除模拟 GPU 隔离。
- 最终必要回归与两批页面验收见验收表/开发记录；不继续加视频、真实 GPU 或外部发布。

### 新增授权：步骤级执行后端

- 本轮先将本地执行提取为后端基线，再接一个真实回环 HTTP 服务；单步骤通过后接固定六步。新任务 execution_backend 冻结为 local/external，不切换已运行任务，不接管任意既有外部作业。
- 中心负责 Attempt、命令持久化、租约/fencing、提交、重试及资源；外部服务负责具体进程、带序号的候选事件和物理退出。两侧计算处理器相同，产物使用共享真实目录。
- 验证启动响应丢失不重复、成功步骤/检查点复用、跨租约、Worker 中断、迟到提交、取消失联和清理隔离；本地与外部证据分开，不能把旧本地验收写成外部通过。默认 30/300 和关闭硬截止不变。

### 当前新增授权：业务驱动、中心授权、步骤托管

- 保留此前外部 A12 与独立实现接入成果，新增 managed-v1；006 只增加登记关闭标志、顺序/输入快照和业务幂等操作表，旧任务默认关闭登记且冻结图不改写。
- 业务 API 只登记/查询/关闭流程。Step 先持久化，按上一条末步骤连接；中心检查依赖、预安装 mock-step 版本与资源后才创建 Attempt。外部派发前使用不能操作 job 的只读协商 token，并在授权事务内重核状态。
- 本地、配套外部、文档独立实现都支持单个 mock-step 的 JSON 批次计算。处理器版本分离，不建设插件体系；输入和参数随注册冻结，不利用任意业务 key 调度动画代码。
- WAITING_STEPS 表示等待下一步或显式 finish，不是完成。finish 只关闭登记；实际步骤未完成或旧执行未确认退出时继续等待。失败/恢复/取消与历史 Attempt 保留。
