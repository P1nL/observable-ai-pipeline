# PRD：可观测 AI 长任务执行管线 MVP

更新：2026-10-25。原交付预算为三天、AI 辅助开发，之后的明确授权增量分别记录，不倒写历史工时。页面仍为监控管理台，无上传/创建；managed-v1 动态顺序托管、六步示例和旧冻结任务兼容保留。最新授权在步骤级托管上加入预配置节点、每节点 CPU 配额/多个模拟设备、受控 HTTPS 与真实共享引用检查；不是重写项目、自动发现或仅状态上报。真实模型/GPU、公网部署及提交/推送仍未授权，完成状态以新增验收为准。

## 1. 问题与目标

动画素材处理包含多个耗时步骤。某一步失败、执行进程中断或运行时间很长时，上游需要知道发生了什么，并尽量复用已经完成的工作。

本项目验证执行可靠性与可解释性，不是模型效果。任务可采用 MOCK，但持久化、领取、重试、接管、检查点和产物提交需要真实实现。

## 2. 用户与关键场景

- 上游服务：提交任务并获取稳定任务 ID，稍后查询结果。
- 操作者：查看步骤依赖、等待原因、执行尝试和错误，发起恢复或基本取消；复杂优先级、抢占和取消策略不在本轮。
- 演示者：注入失败或杀死 Worker，展示恢复前后哪些工作被复用。

用户故事：

1. 提交后不保持 HTTP 连接，关闭页面或重启 API 也不影响独立 Worker。
2. 编码失败时只重新编码，不再次生成动画帧。
3. 帧生成途中 Worker 退出，新 Attempt 从已经提交的批次继续。
4. 多个任务等待同一个模拟 GPU 槽位时，展示排队而不是错误或虚假进度。
5. 模型正常运行超过一个租约周期仍不被中断。
6. 旧 Worker 恢复时，迟到结果不能覆盖新 Attempt 的结果。

## 3. 功能范围

### 必须交付

- 新任务可用 `managed-v1` 动态顺序托管；`animation-dag-v2` 六步轻量 DAG 保留为默认动画示例；原 `animation-v1` 不再新建，已有冻结任务的查询、执行/恢复与产物继续支持。不接受任意用户代码、拖拽编辑器或通用插件。
- Task / Step / Attempt 三层对象与持久化历史。
- 独立 API / Worker、数据库队列和产物存储；协调逻辑不建设独立调度微服务。
- 可分类、有限次的步骤自动重试，以及人工恢复。
- 租约续期、独立心跳、失联接管和旧执行代次隔离。
- 同一任务恢复时跳过成功步骤，复用已提交产物和检查点；增强另提供限定单用户作用域、可绕过且记录来源的兼容跨任务缓存。
- 帧生成 MOCK 的批次检查点，明确其他步骤的重跑边界。
- legacy 单槽兼容，以及预配置节点所属模拟设备的互斥、等待、失联隔离；确认原执行退出后才复用，不把未知状态释放给新 owner。
- 查询 API 与任务监控管理台：概览、筛选队列、依赖图、历史页签、取消/人工恢复和真实产物预览。页面移除上传/创建表单，后端提交 API 保留给上游和演示命令。不建设完整前端、账号权限或运维平台。
- 有界故障演示、启动说明、实际验收记录和开发总结。
- 后端保留 PNG/JPEG 上传与稳定输入引用、真实 GIF 和 JSON，不因页面收缩删除已有素材/媒体处理。限制仍为 8 MiB、16MP、边长 8192，归一化最长边 256、最多 120 帧；不支持视频或动画图片。后续步骤托管不扩大媒体格式范围，独立 MOCK 只输出 synthetic JSON，不冒充 GIF。
- 基本取消：阻止新派发，在途进程退出并确认清理后才 CANCELED；身份不明保持 CANCELING/隔离，取消与成功提交由数据库锁和 fencing 决定先后。
- 第二批：normalize_asset 后分叉 segment_subject / analyze_motion，再汇合 generate_frames → encode_package → publish_result；CPU 容量与单模拟 GPU 槽位约束并行，最后一步仅幂等提交本系统引用。
- 本次步骤级托管：local 为默认，新任务可冻结 external 路由；中心持久化每步启动命令、绑定执行器和外部作业，独立服务复用现有处理器，中心仍决定重试/代次和产物提交。稳定幂等启动、独立监督、认证绑定、检查点复用与退出确认必须真实验证。

- 后续接入验证：先补外部路径 A12，再提供文档可独立实现的协议与版本/能力检查；独立执行器不能导入中心模块或包装 app.executor。保留配套实现，分别验收真实六步、响应丢失幂等、恢复/迟到隔离与取消退出清理，不建设通用插件或多节点平台。

- 最新授权的业务顺序托管：业务按需登记 Step，中心持久化并检查依赖、已支持处理器/版本和资源，授权后才创建 Attempt 并执行。登记必须幂等且配置不可变，恢复先读历史再续登记；进度描述不是 Step，finish 只关闭登记，不代替实际执行/提交/退出。开放流程不能因当前已登记步骤全成功而自动终结。只扩展动态顺序，不扩展动态并行或任意代码。

- 后续批准的节点增量：静态清单中独立身份/凭据、处理器版本、接单状态、CPU 预算和多模拟设备；繁忙/失联/挂载不可用时可选择其他兼容节点。同一 Attempt 固定节点/资源/作业/状态库身份，跨节点恢复只复用已提交兼容检查点。资源监控展示实际归属及事件，不授予强制释放权限。真实跨设备连接须有机器、权限、验证 HTTPS 和共享盘，不由同机验证推定完成。

### 不在 MVP 内

通用 DAG 编辑器、动态并行/循环、任意代码/插件平台、任意已有外部作业接管、跨机文件复制、多执行器自动发现/自动伸缩或负载均衡平台、分布式缓存/同键计算合并、真实模型/GPU/DCGM、独立调度微服务、外部发布、完整权限/监控平台、WebSocket、复杂取消/抢占、完整前端、公网部署及数据库/存储损毁灾备。预配置节点的简单选择不扩展成注册中心或分布式调度平台。

## 4. 动态顺序托管、六步示例与历史兼容

managed-v1 不预先要求总步骤数。业务以历史提交结果决定下一步，登记固定输入/参数/版本与前驱；中心授权具体一次执行。显式 finish 后仍等待实际步骤成功和清理确认。首版处理器为预安装 mock-step，输入是合成 JSON，不开放动态并行或任意命令。下列六步保留为动画业务示例，不是所有任务的强制结构。

| 步骤 | 依赖 | 资源 | 恢复边界 |
| --- | --- | --- | --- |
| normalize_asset / 素材准备 | 无 | CPU，合成或已上传静态图 | 同任务成功产物复用 |
| segment_subject / 主体分割 | normalize_asset | CPU MOCK | 成功分支复用 |
| analyze_motion / 动作分析 | normalize_asset | CPU MOCK，与分割独立 | 成功分支复用 |
| generate_frames / 模拟 GPU 帧生成 | segment_subject + analyze_motion | CPU MOCK，由单模拟 GPU 槽位互斥控制 | 已提交批次检查点 |
| encode_package / 编码打包 | generate_frames | CPU，图片输入为真实 GIF 编码 | 复用帧，仅重跑打包 |
| publish_result / 结果提交 | encode_package | CPU，仅本系统清单 | 当前任务独立提交，不跨任务缓存 |

AI 分割、分析和生成仍为确定性 MOCK，明确标注来源；上传、像素读取、PNG 帧与 GIF 编码必须真实。旧合成任务继续保持原 JSON 行为，不能用 JSON 改扩展名冒充媒体。新六步版本由 publish_result 幂等提交本系统结果引用；两版都不向第三方发布。

新版本不改写既有三步任务的冻结图、Attempt 或成功引用。跨任务缓存只接受成功提交且可读取的兼容产物，以实际输入/上游字节指纹、步骤与版本、参数、seed/生成标识和作用域建键；任务级发布不直接缓存，取消、失败及候选不能冒充成功来源。

旧三步已退出新任务入口；已有三步仍为 normalize_asset → generate_frames → encode_package，末步按原冻结协议提交结果。旧任务不是新的六步任务，不做数据迁移或冒充六步展示。

### 阶段验收范围

原 MVP、恢复、A12 和页面验收历史保留；新增第一批有真实上传/GIF/取消的 API 和浏览器证据，完成必要回归后才进入第二批。第二批只按新增 DAG/并行/缓存验收，不将进入阶段或静态文档当作通过；两批及相应文档完成后收尾。

用户后续授权的监控台调整只扩展展示和只读聚合查询：全库真实计数、队列搜索/筛选/分页、节点详情、Attempt/事件/结果、资源异常提示。新增能力及直接回归完成即停止，不由“后台”推定账号系统、分布式调度或完整监控平台授权。

最新阶段另行验证外部 A12、文档独立执行器，以及动态顺序托管的登记幂等、授权隔离、业务恢复、等待下一步、显式结束和资源清理。历史流程回归保留；新能力必须有新运行证据，不能由既有动画验收推定通过。

## 5. 完成优先与约束

- 正常执行可持续续租，不因经过 300 秒或页面请求超时而终止。
- 默认步骤硬时限和任务总截止时间均不启用；长时间无进展触发观测和告警，不直接判死。
- 用户可显式配置硬时限；配置创建时冻结并可查询。基本取消需确认退出/隔离，不建设复杂取消体系。
- 不可恢复错误和重试耗尽仍可导致失败；人工恢复保留已有成功工作。
- 不承诺无限等待必然完成。执行环境、资源和外部依赖需要恢复到可用状态。

## 6. 成功标准

最终 MVP 以 [验收场景](ACCEPTANCE.md) 为准，包括正常完成、有限重试、中断后检查点恢复、同任务成功步骤复用、单模拟 GPU 排队/隔离、旧 Attempt 拒绝和跨租约运行。第一步不要求一次完成这些能力。

每个场景都要能通过 API 查看 Task、Step、Attempt、事件和产物来源。仅看页面颜色变化不构成恢复验收。

## 7. 交付

公开源码、可用启动配置、合成及可上传图片示例和简要 Markdown 即可满足交付选项；本次不执行提交/推送。公网与真实 GPU 不在本轮范围内。

AI 工具、token、人工时间和实际失败案例应持续记录，不在最终交付前回忆编造。个人时间与 AI 自动运行时间分开。
