# PRD：可观测 AI 长任务执行管线 MVP

日期：2026-10-24。状态：规划基线，功能尚未实现。

## 1. 问题与目标

动画素材处理包含多个耗时步骤。某一步失败、执行进程中断或运行时间很长时，上游需要知道发生了什么，并尽量复用已经完成的工作。

本项目验证执行可靠性与可解释性，不是模型效果。任务可采用 MOCK，但持久化、领取、重试、接管、检查点和产物提交需要真实实现。

## 2. 用户与关键场景

- 上游服务：提交任务并获取稳定任务 ID，稍后查询结果。
- 操作者：查看步骤依赖、等待原因、执行尝试和错误，发起恢复或取消。
- 演示者：注入失败或杀死 Worker，展示恢复前后哪些工作被复用。

用户故事：

1. 提交后不保持 HTTP 连接，关闭页面也不影响执行。
2. 编码失败时只重新编码，不再次生成动画帧。
3. 帧生成途中 Worker 退出，新 Attempt 从已经提交的批次继续。
4. 多个任务等待一张 GPU 时，展示排队而不是错误或虚假进度。
5. 模型正常运行超过一个租约周期仍不被中断。
6. 旧 Worker 恢复时，迟到结果不能覆盖新 Attempt 的结果。

## 3. 功能范围

### 必须交付

- 固定、版本化 DAG；创建时校验无环和依赖存在。
- Task / Step / Attempt 三层对象与持久化历史。
- 独立 Worker、协调器、数据库队列和产物存储。
- 可分类、有限次的步骤自动重试，以及人工恢复。
- 租约续期、独立心跳、失联接管和旧执行代次隔离。
- 同任务成功步骤复用，以及受控的跨任务缓存。
- 帧生成 MOCK 的批次检查点，明确其他步骤的重跑边界。
- CPU/GPU 分队列、整卡独占槽位及不确定资源隔离。
- 查询 API、任务详情与资源视图。
- 有界故障演示、启动说明、实际验收记录和开发总结。

### 不在 MVP 内

多机高可用、自动扩缩容、GPU 抢占/切片、多卡训练、任意 DAG 编辑器、多租户计费、真实 AI 效果评估、数据库/存储损毁后的灾备。

## 4. 示例 DAG

| 步骤 | 依赖 | 资源 | 恢复边界 |
| --- | --- | --- | --- |
| normalize_asset | 无 | CPU | 本步骤重跑 |
| segment_subject | normalize_asset | GPU | 本步骤重跑或复用成功结果 |
| analyze_motion | normalize_asset | GPU | 本步骤重跑或复用成功结果 |
| generate_frames | segment_subject, analyze_motion | GPU | 已提交批次检查点 |
| encode_package | generate_frames | CPU | 复用帧，仅重跑编码 |
| publish_result | encode_package | CPU/I/O | 幂等发布结果引用 |

AI MOCK 产物必须明确标注来源。publish_result 只发布本系统结果清单，不向第三方平台发送素材。

## 5. 完成优先与约束

- 正常执行可持续续租，不因经过 300 秒或页面请求超时而终止。
- 默认步骤硬时限和任务总截止时间均不启用；长时间无进展触发观测和告警，不直接判死。
- 用户可显式配置硬时限或取消；配置创建时冻结并可查询。
- 不可恢复错误和重试耗尽仍可导致失败；人工恢复保留已有成功工作。
- 不承诺无限等待必然完成。执行环境、资源和外部依赖需要恢复到可用状态。

## 6. 成功标准

以 [验收场景](ACCEPTANCE.md) 为准，至少展示正常完成、临时错误重试、中断后检查点恢复、结果复用、GPU 排队、旧 Attempt 拒绝和运行跨租约周期。

每个场景都要能通过 API 查看 Task、Step、Attempt、事件和产物来源。仅看页面颜色变化不构成恢复验收。

## 7. 交付

优先交付公开源码仓库、一键启动配置、演示素材和简要 Markdown。公网演示可选。真实 GPU 接入可选，但必须清楚区分 MOCK 调度验收和真实硬件验证。

AI 工具、token、人工时间和实际失败案例应持续记录，不在最终交付前回忆编造。个人时间与 AI 自动运行时间分开。
