## 第一优先级

文档基线后立即推进 P1，不先建设复杂 UI、监控平台或通用工作流框架。P2 恢复语义跑通后再做可视化表现。

## 开工前已经明确的默认决策

- 当前新建可选 managed-v1 动态顺序托管，六步保留默认业务示例，历史三步按原版本冻结并继续执行/恢复；独立 API / Worker，恢复扫描在 Worker 内，不建设独立调度微服务。coordinator 仅兼容入口。
- PostgreSQL 是事实来源，不额外引入 Redis。
- 产物首先使用持久化文件卷。
- 正常续租不受单个租约周期限制；默认不设硬执行时限和任务截止时间。
- 原 MVP/legacy 保持一个 MOCK GPU 槽位；后续批准的配置节点有各自配额/模拟设备，仍全部为 CPU MOCK，不自动发现节点或接真实 GPU。
- 计算允许重复，结果提交需要幂等和执行代次隔离。
- 不改动现有其他项目；不为本 MVP 新增完整分布式调度系统。

## 后续迭代（不在三天强制交付）

- 通用 DAG 编辑器、跨机缓存/计算合并/清理平台、外部发布系统、真实 GPU/模型/DCGM、多节点资源发现和分布式调度仍为后续；本轮已纳入的固定六步并行与有限跨任务缓存不再列为未实现。
- 完整监控平台、WebSocket、复杂取消/优先级/抢占、完整前端和公网服务不在三天承诺内。
- 不能削减：Attempt 历史、持久化状态、失联接管、fencing、检查点协议、GPU 不确定资源隔离和明确验收。
- 真实 GPU、外部模型、DCGM、自动发现和分布式调度平台不进入本次交付；已批准的静态节点范围不再列为未授权。

进入某阶段不代表完成。退出条件必须有运行记录；静态文档或 JSON 检查不能计作故障恢复通过。需要改变范围时先更新 PRD 和执行规范，再实施必要变化。
